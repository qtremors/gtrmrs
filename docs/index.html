[TOOLS]

Core Developer Utilities

Four focused utilities designed to run standalone or through the unified gtrmrs entrypoint.

locr Lines of Code Counter

Fast, Git-aware lines of code counter supporting 25+ programming languages. Understands multi-line and single-line comment syntax without third-party lexers.

  • --stats : Breakdown percentage distribution
  • --tests : Filter and count only test suite code
  • --top : Rank the top 15 largest files
  • --json : Output structured machine data
$ locr --stats --top
rtree Directory Tree Visualizer

Generates clean, readable directory tree representations. Automatically prunes heavy build artifacts and caches before scanning.

  • --depth N : Control folder traversal depth
  • --flat : Output flat path list instead of tree
  • -r <path> : Target a specific directory
  • -o <file> : Export visual tree directly to file
$ rtree -r app --depth 2
deps Dependency Catalog Auditor

Audits multi-repository Gradle version catalogs (libs.versions.toml), detects version drift across projects, queries upstream registries, and performs safe in-place updates.

  • --align : Synchronize repos to highest version found
  • --update : Upgrade to latest upstream stable releases
  • --dry-run : Preview line changes without writing
  • --html --open : Generate standalone interactive HTML report
$ deps --align --dry-run
gitmig Repository Migrator

Copies or archives Git repositories without giant dependency folders (node_modules, venv, build, .git). Safely preserves .env and .gitignore files.

  • --dry-run : Preview migration operations and sizes
  • --zip : Output direct compressed archive
  • --git-size : Analyze sorted repository storage footprint
  • --env : Backup only environment configurations
$ gitmig ./backup --dry-run
[ARCHITECTURE]

Design & Performance

Engineering decisions behind gtrmrs's speed and reliability.

Pure Python Standard Library
Zero third-party pip dependencies. Implemented exclusively with os, sys, subprocess, fnmatch, and urllib. Instant installation, zero supply chain risk, and zero native compilation steps.
2-Phase Hybrid Scanning
Phase 1 eagerly matches folder names against heavy directory patterns during os.walk, skipping entire trees before recursing. Phase 2 applies Git ignore checks for 100% path accuracy.
Android & Multi-Module Native
First-class support for multi-module Gradle setups. Prunes build/, .gradle/, .cxx/, and Room SQLite schemas/ while parsing version catalogs, wrappers, and SDK target levels.
Dual Calling Convention
Run commands individually (locr, rtree, deps, gitmig) or grouped under the gtrmrs <subcommand> entrypoint. Also runs directly via python -m gtrmrs.cli.

[FAQ]

Frequently Asked Questions

Why is gtrmrs not on PyPI?
gtrmrs is intentionally maintained as a direct, local source repository. Installing locally via git clone and pip install -e . gives you full control and zero dependency supply chain baggage.
Does gtrmrs require internet access?
No. locr, rtree, and gitmig are 100% offline. The deps tool works completely offline when passed --no-upstream, and only connects to public Maven and Gradle registries when querying for upstream version updates.
How does eager directory pruning work?
During directory walking, folder names are compared against known build and cache signatures (build, .gradle, .cxx, node_modules, schemas, venv). Matching folders are pruned immediately before walking child directories, resulting in 40x+ faster scans.
What operating systems are supported?
Windows, macOS, and Linux are all natively supported. The codebase uses only Python standard library cross-platform path utilities and ANSI coloring.
